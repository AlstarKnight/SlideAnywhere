# 流畅度和耗电：现状和改动

_2026-10-27，读代码得出的结论，没有在真机上测量（云端没有手机和模拟器）。用户要求：性能优先，流畅和耗电要平衡。_

## 面板关着时在做什么

- `PanelService`（前台服务）只挂着一个边缘触发条或悬浮图标的小窗口，平时不重绘、不轮询。
- 面板窗口和里面的 Compose 界面在关闭时整个移除，电池卡片的广播、存储卡片每 2 秒的刷新、小部件更新（`WidgetHost.startListening`）都只在面板打开时运行。
- 手电筒状态回调（`ItemLauncher` 里的 `TorchCallback`）一直注册着，只在手电筒或相机状态变化时触发，开销可以忽略。
- **无障碍服务原来一直在收窗口事件**：每次窗口变化（切应用、弹窗、通知栏、键盘）都会被叫醒，并且再向系统要一次窗口列表。PR #4 改成只在需要时才收：
  - 设了黑名单（非空）或白名单，或某一页设了情景模式时，才收「窗口状态变化」来判断前台应用；
  - 触发方式是悬浮图标并且开了「躲开键盘」时，才收「窗口变化」来找键盘位置；
  - 都不需要时一个事件都不收，无障碍只用来执行锁屏、截图等动作。

## 面板打开和操作时

- R8 优化（PR #4）本身让 Compose 运行明显更快；debug 包没有 R8，比 release 慢，试用请装 release 包。
- 应用图标按尺寸缓存在内存（最多 200 个），服务活着时再次打开面板不再从系统读取。
- PR #4 修掉的多余工作：
  - 便签打字、拖动卡片外观滑块时，每改一下都把整个配置序列化并同步写盘；现在等停下 0.5 秒再写一次。
  - 最近/常用应用卡片每次打开面板都读取全部应用的名字并算拼音，现在只读卡片上显示的那几个。
  - 亮度滑块拖动时每一帧都写两次系统设置（模式 + 亮度），音量滑块同一档也反复设置；现在只在数值变化时写，手动模式每次拖动只设一次。

## 没做的，可以以后再看

- 面板每次打开都重新创建界面（关闭时为了省电全部释放）。如果打开那一下觉得慢，可以考虑预先建好隐藏窗口，代价是常驻内存和更多复杂度。（未验证是否有感知）
- 应用抽屉、添加应用时每次都重新读取全部应用列表；如果打开慢，可以加缓存，用 `PackageManager.getChangedPackages` 判断是否需要刷新。（未验证是否有感知）
- 没有自己的 Baseline Profile；库自带的已经生效。要做需要能跑真机或模拟器的环境。

## 以后开发要注意

- 往无障碍服务加新的事件用途时，要同时改 `ActionAccessibilityService.updateTracking`，否则收不到事件。
- 面板里会被高频触发的输入（滑块、文本框）不要每次都做 IPC 或写盘，只在值变化时做。
